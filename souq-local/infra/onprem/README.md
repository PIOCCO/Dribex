# Dribex On-Prem Production (Ubuntu)

Production Docker Compose stack for **public Internet** deployment.

## Architecture

```text
PUBLIC INTERNET
      |
      | HTTPS :443
      v
    NGINX  (only public entry point — ports 80/443)
      |
      +----> Web :3000
      |
      +----> API :8000
                 |
     PostgreSQL | Redis | MinIO | Vault (internal network only)
                 |
     Prometheus | Loki | Grafana (internal — SSH tunnel for admin)
```

Only **nginx** exposes host ports `80` and `443`. Postgres, Redis, MinIO, Vault, API, and Web are **not** published on the public interface.

**Tailscale** remains for SSH and private admin access only — not for end-user traffic.

## Canonical production deploy

From the **`souq-local`** repository root (includes backup, Alembic migrations, health check):

```bash
cp infra/onprem/env.prod.example infra/onprem/.env.prod
# Edit secrets — never commit .env.prod

chmod +x infra/onprem/scripts/validate-production-env.sh
infra/onprem/scripts/validate-production-env.sh infra/onprem/.env.prod

./scripts/production-deploy.sh
```

Pre-deploy backup failure **stops** the deploy unless you set `SKIP_PRE_DEPLOY_BACKUP=1` (emergency only).

### Vault (bootstrap limitation)

The bundled **HashiCorp Vault** container runs in **file storage mode with TLS disabled** on the internal Docker network. It is suitable for **bootstrap/lab only**. Before a public launch, either initialize Vault properly (TLS, unseal, Vault Agent) or inject secrets only via `.env.prod` with a documented secret-rotation process. Do not expose Vault’s listener on the public Internet.

### Auxiliary script (no migrations)

`scripts/deploy.sh` in **this directory** rebuilds images and runs `docker compose up -d` **without** Alembic. Use it only when migrations are already applied (e.g. quick image rebuild). **Do not** use it for first-time production install or schema upgrades.

## TLS (required for public mobile)

Replace bootstrap self-signed certs before public launch:

1. **Cloudflare Origin Certificate** (if using Cloudflare proxy) — see `docs/PUBLIC_TLS_SETUP.md`
2. **Let's Encrypt** — if the server is directly reachable on port 443

Install files as:

- `nginx/certs/fullchain.pem`
- `nginx/certs/privkey.pem`

Then: `docker compose -f docker-compose.prod.yml --env-file .env.prod restart nginx`

Bootstrap self-signed certs may be auto-generated by `deploy.sh` when certs are missing — **not** valid for public mobile apps.

## Media / MinIO

Media is served **only through the API** at `/media/{bucket}/{key}` with authorization checks.

- Do **not** set `MINIO_PUBLIC_URL` in production.
- Nginx does **not** expose `/storage/` (direct MinIO proxy removed).

## Backups and restore

**Backup** (PostgreSQL + all MinIO buckets):

```bash
./scripts/backup.sh
```

Schedule via cron. Copy `/var/backups/margem` off-server (override with `BACKUP_DIR`).

**Restore** (destructive — requires typing `RESTORE`):

```bash
# Full stack (DB + matching minio-YYYYMMDD-HHMMSS directory)
./scripts/restore.sh --full /var/backups/margem/postgres-YYYYMMDD-HHMMSS.sql.gz

# PostgreSQL only
./scripts/restore.sh --postgres /var/backups/margem/postgres-YYYYMMDD-HHMMSS.sql.gz

# MinIO only
./scripts/restore.sh --minio /var/backups/margem/minio-YYYYMMDD-HHMMSS
```

Restore drops and recreates the PostgreSQL database and can overwrite MinIO bucket contents. Stops API/web before recovery.


## Monitoring

Grafana is internal-only. Access via SSH tunnel:

```bash
ssh -L 3000:127.0.0.1:3000 user@your-server
docker compose -f docker-compose.prod.yml --env-file .env.prod port grafana 3000
```

Prometheus scrapes the API `/metrics` endpoint on the internal network.

## Tailscale admin UI (optional)

See `docker-compose.admin-tailscale.yml`. Binds admin UI to **`TAILSCALE_IP` only** — validated by `validate-compose-ports.sh`.
